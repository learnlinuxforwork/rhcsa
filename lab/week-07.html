Lab guide 7

Networking and firewalld

Configure addressing, name resolution, and a firewall that all survive a reboot without you touching anything.

3-4 hours Week 6 complete
Before you start
  • Week 6 complete
  • Console access in case you cut off your own SSH session
  • Take a snapshot of both machines. You will break things on purpose.

1. Look before you change

Record the current state so you can get back if something goes wrong.

Current addressing and routing
ip addr show
ip route show
ip -6 addr show
nmcli device status
nmcli connection show
Save a copy of what works
nmcli connection show --active | tee ~/net-before.txt
ip addr show | tee -a ~/net-before.txt

2. Configure a static IPv4 address

Use nmcli. Changes made with 'ip' alone disappear at reboot and score nothing.

Identify the connection, then modify it
CONN=$(nmcli -g NAME connection show --active | head -1)
echo "$CONN"
sudo nmcli connection modify "$CONN" ipv4.method manual ipv4.addresses 192.168.56.10/24 ipv4.gateway 192.168.56.1 ipv4.dns '1.1.1.1 9.9.9.9'
Apply and confirm
sudo nmcli connection down "$CONN" && sudo nmcli connection up "$CONN"
ip addr show
ip route show
cat /etc/resolv.conf
Worth knowing

Adjust the addresses to match your own lab network. The method matters more than the numbers: ipv4.method manual plus an explicit address is what makes it persistent.

3. Add IPv6

The objectives name IPv6 explicitly, and it is often skipped in practice.

A static IPv6 address on the same connection
sudo nmcli connection modify "$CONN" ipv6.method manual ipv6.addresses 2001:db8:56::10/64
sudo nmcli connection up "$CONN"
ip -6 addr show
ping6 -c 2 ::1

4. Hostname and name resolution

Set the hostname permanently
hostnamectl
sudo hostnamectl set-hostname servera.lab.example.com
hostnamectl
hostname -f
Static resolution and testing
echo '192.168.56.11  serverb serverb.lab.example.com' | sudo tee -a /etc/hosts
getent hosts serverb
ping -c 2 serverb
dig +short redhat.com
nslookup serverb

5. Networking at boot

Make sure it comes up by itself
sudo systemctl enable --now NetworkManager
sudo nmcli connection modify "$CONN" connection.autoconnect yes
nmcli -f connection.autoconnect connection show "$CONN"

6. firewalld

Everything permanent needs --permanent followed by --reload. Forgetting that is the classic mistake.

Inspect the current state
sudo systemctl enable --now firewalld
sudo firewall-cmd --state
sudo firewall-cmd --get-active-zones
sudo firewall-cmd --list-all
Open a named service permanently
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --reload
sudo firewall-cmd --list-services
Open a specific port, and a port range
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --permanent --add-port=9000-9010/udp
sudo firewall-cmd --reload
sudo firewall-cmd --list-ports
Remove something, and change the default zone
sudo firewall-cmd --permanent --remove-port=9000-9010/udp
sudo firewall-cmd --reload
sudo firewall-cmd --get-default-zone
sudo firewall-cmd --list-all --zone=public
Worth knowing

'firewall-cmd --list-all' shows the RUNTIME configuration. To check what will survive a reload, add --permanent. If the two disagree, you forgot --reload.

Verify your work

Run these before you consider the lab finished.

  1. ip addr show | grep -E 'inet |inet6 '
  2. sudo firewall-cmd --permanent --list-all
  3. getent hosts serverb
  4. reboot, then re-run every command above and confirm nothing was lost
Break it, then fix it

Break:

sudo firewall-cmd --add-service=http   # note: no --permanent

What you'll see: The service is reachable right now. After 'firewall-cmd --reload' or a reboot, it is blocked again.

Fix:

sudo firewall-cmd --permanent --add-service=http && sudo firewall-cmd --reload

Why it matters: firewalld keeps runtime and permanent configuration separately. A rule without --permanent is a rule that scores zero on a performance-based exam. Make '--permanent then --reload' a single muscle memory.

Now reboot

Run sudo reboot, then re-run every command in the verify list above. Anything that did not come back on its own would have scored zero on the exam. Fix it now, while you can still see what you did.
