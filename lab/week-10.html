Lab guide 10

SELinux, SSH Keys, and Default Permissions

Work with SELinux rather than around it, set up key-based authentication, and control default permissions. This domain fails more candidates than any other.

4-5 hours Week 9 complete
Before you start
  • Week 9 complete
  • Both machines reachable
  • A snapshot before you start
  • Take a snapshot of both machines. You will break things on purpose.

1. Modes

Enforcing blocks and logs. Permissive only logs. Disabled does neither - and is never the right answer on the exam.

Check and switch at runtime
getenforce
sestatus
sudo setenforce 0
getenforce
sudo setenforce 1
getenforce
Make the mode persistent
sudo cat /etc/selinux/config | grep -v '^#'
sudo sed -i 's/^SELINUX=.*/SELINUX=enforcing/' /etc/selinux/config
grep '^SELINUX=' /etc/selinux/config
Worth knowing

setenforce changes the current mode only. The file is what applies at boot. A task that says 'SELinux must be enforcing' means both.

2. Read contexts

Every file and process carries a context. The fourth field - the type - is what usually matters.

Files, processes, ports, and users
ls -Z /var/www/html 2>/dev/null || sudo mkdir -p /var/www/html && ls -Zd /var/www/html
ps -eZ | grep sshd | head -3
id -Z
sudo semanage port -l | grep -w http_port_t

3. Fix a context the right way

This is the classic exam scenario: content served from a non-default location.

Set up a web server with content in the wrong place
sudo dnf install -y httpd
sudo systemctl enable --now httpd
sudo firewall-cmd --permanent --add-service=http && sudo firewall-cmd --reload
sudo mkdir -p /srv/mysite
echo '<h1>Lab site</h1>' | sudo tee /srv/mysite/index.html
ls -Zd /srv/mysite
Point httpd at it and watch it fail
sudo sed -i 's|^DocumentRoot .*|DocumentRoot "/srv/mysite"|' /etc/httpd/conf/httpd.conf
sudo systemctl restart httpd
curl -s -o /dev/null -w '%{http_code}\n' http://localhost/
sudo journalctl -t setroubleshoot --no-pager | tail -5
sudo ausearch -m AVC -ts recent 2>/dev/null | tail -20
Fix it permanently with semanage plus restorecon
sudo dnf install -y policycoreutils-python-utils
sudo semanage fcontext -a -t httpd_sys_content_t '/srv/mysite(/.*)?'
sudo restorecon -Rv /srv/mysite
ls -Zd /srv/mysite
ls -Z /srv/mysite
curl -s http://localhost/
Worth knowing

chcon would also have worked right now - and would be wiped by the next relabel. semanage fcontext writes the rule into policy; restorecon applies it. That pairing is the correct, persistent answer.

4. Port labels

Running a service on a non-standard port needs the port labelled, or SELinux blocks the bind.

Move httpd to port 8888
sudo sed -i 's/^Listen 80$/Listen 8888/' /etc/httpd/conf/httpd.conf
sudo systemctl restart httpd   # this fails
sudo systemctl status httpd --no-pager | tail -5
Label the port, then it starts
sudo semanage port -a -t http_port_t -p tcp 8888
sudo semanage port -l | grep -w http_port_t
sudo systemctl restart httpd
sudo firewall-cmd --permanent --add-port=8888/tcp && sudo firewall-cmd --reload
curl -s http://localhost:8888/

5. Booleans

Booleans switch predefined policy behaviour on and off. -P makes the change survive a reboot.

Find and set one
getsebool -a | head
getsebool -a | grep httpd | head -10
getsebool httpd_enable_homedirs
sudo setsebool -P httpd_enable_homedirs on
getsebool httpd_enable_homedirs
See what a boolean actually does
sudo semanage boolean -l | grep httpd_enable_homedirs
Worth knowing

Without -P the change is lost at reboot. Given the persistence rule, a boolean set without -P scores nothing.

6. Read a denial

Being able to interpret the log is the skill; the fix follows from it.

Find and translate
sudo ausearch -m AVC -ts today 2>/dev/null | tail -20
sudo journalctl -t setroubleshoot --no-pager | tail
# sealert gives a plain-English explanation when setroubleshoot is installed:
sudo dnf install -y setroubleshoot-server 2>/dev/null
sudo sealert -a /var/log/audit/audit.log 2>/dev/null | head -30

7. Key-based SSH authentication

Generate a key and install it
ssh-keygen -t ed25519 -C 'shea@servera' -f ~/.ssh/id_ed25519 -N ''
ls -l ~/.ssh/
ssh-copy-id shea@serverb
ssh shea@serverb 'echo key auth works; hostname'
Confirm the permissions SSH insists on
ssh shea@serverb 'ls -ld ~/.ssh; ls -l ~/.ssh/authorized_keys'
# ~/.ssh must be 700 and authorized_keys 600, or sshd ignores them
Optionally disable password authentication
ssh shea@serverb "sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config && sudo systemctl restart sshd"

8. Default permissions with umask

See the effect
umask
touch ~/umask-default.txt
mkdir ~/umask-default-dir
ls -l ~/umask-default.txt
ls -ld ~/umask-default-dir
Change it for this shell, then persistently
umask 0077
touch ~/umask-private.txt
ls -l ~/umask-private.txt
echo 'umask 0077' >> ~/.bashrc
System-wide default
grep -rn umask /etc/profile /etc/bashrc | head
Worth knowing

umask subtracts from 666 for files and 777 for directories. 0077 gives 600 files and 700 directories - private to the owner.

Verify your work

Run these before you consider the lab finished.

  1. getenforce # must say Enforcing
  2. grep '^SELINUX=' /etc/selinux/config
  3. ls -Zd /srv/mysite | grep httpd_sys_content_t
  4. sudo semanage port -l | grep -w http_port_t | grep 8888
  5. getsebool httpd_enable_homedirs
  6. reboot, then re-run all of the above
Break it, then fix it

Break:

sudo chcon -t user_home_t /srv/mysite/index.html && sudo restorecon -Rv /srv/mysite

What you'll see: You set a context with chcon, then restorecon immediately reverted it - because policy disagreed with you.

Fix:

That IS the correct behaviour. Use: sudo semanage fcontext -a -t httpd_sys_content_t '/srv/mysite(/.*)?' && sudo restorecon -Rv /srv/mysite

Why it matters: chcon is a temporary label; semanage fcontext is a policy rule. If a fix disappears after a relabel or reboot, you used chcon where you needed semanage. Never solve an SELinux problem by setting permissive - the exam grades the security domain, and permissive fails it.

Now reboot

Run sudo reboot, then re-run every command in the verify list above. Anything that did not come back on its own would have scored zero on the exam. Fix it now, while you can still see what you did.
