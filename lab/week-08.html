Lab guide 8

Partitions, Filesystems, and Swap

Carve up the spare disk, format it three ways, mount it persistently by UUID, and add swap - all without destroying the system.

3-4 hours Week 7 complete
Before you start
  • Week 7 complete
  • A second, empty disk attached to servera
  • A snapshot taken immediately before you start
  • Take a snapshot of both machines. You will break things on purpose.

1. Identify the right disk

Get this wrong and you will reinstall. Confirm the device before every destructive command.

Which disk is spare?
lsblk
sudo fdisk -l
sudo blkid
df -h
Set a variable so you cannot mistype it later
DISK=/dev/sdb        # change this to match YOUR spare disk
lsblk $DISK
sudo blkid $DISK || echo 'no filesystem signature - good, it is empty'
Worth knowing

If lsblk shows a mountpoint or existing data on your candidate disk, stop and pick a different one.

2. Create GPT partitions

Write a GPT label and two partitions
sudo parted -s $DISK mklabel gpt
sudo parted -s $DISK mkpart primary 1MiB 2GiB
sudo parted -s $DISK mkpart primary 2GiB 4GiB
sudo parted -s $DISK print
lsblk $DISK
Make sure the kernel noticed
sudo partprobe $DISK
lsblk $DISK

3. Create filesystems

All three named types appear in the objectives.

XFS and ext4
sudo mkfs.xfs ${DISK}1
sudo mkfs.ext4 ${DISK}2
sudo blkid ${DISK}1 ${DISK}2
Label them, which makes fstab easier to read
sudo xfs_admin -L labxfs ${DISK}1
sudo e2label ${DISK}2 labext4
sudo blkid ${DISK}1 ${DISK}2

4. Mount, then make it permanent

Mounting by device name is fragile - device names can change between boots. Use UUID or label.

Mount by hand first to prove it works
sudo mkdir -p /mnt/xfsdata /mnt/extdata
sudo mount ${DISK}1 /mnt/xfsdata
sudo mount ${DISK}2 /mnt/extdata
df -h | grep mnt
sudo umount /mnt/xfsdata /mnt/extdata
Add persistent entries by UUID
sudo cp /etc/fstab /root/fstab.backup
UUID1=$(sudo blkid -s UUID -o value ${DISK}1)
UUID2=$(sudo blkid -s UUID -o value ${DISK}2)
echo "UUID=$UUID1  /mnt/xfsdata  xfs   defaults  0 0" | sudo tee -a /etc/fstab
echo "UUID=$UUID2  /mnt/extdata  ext4  defaults  0 0" | sudo tee -a /etc/fstab
cat /etc/fstab
Test WITHOUT rebooting - this is the safety net
sudo mount -a
df -h | grep mnt
sudo systemctl daemon-reload
Worth knowing

'mount -a' is the single most important habit in this lab. A typo in fstab can stop the system booting; mount -a catches it while you can still fix it.

5. A VFAT filesystem

Named in the objectives, and quick to do with a small third partition.

Add and format it
sudo parted -s $DISK mkpart primary fat32 4GiB 5GiB
sudo partprobe $DISK
sudo mkfs.vfat -n LABVFAT ${DISK}3
sudo mkdir -p /mnt/vfatdata
UUID3=$(sudo blkid -s UUID -o value ${DISK}3)
echo "UUID=$UUID3  /mnt/vfatdata  vfat  defaults  0 0" | sudo tee -a /etc/fstab
sudo mount -a
df -h | grep vfat

6. Add swap non-destructively

The objectives say 'non-destructively' - meaning without disturbing what is already there.

A swap partition
sudo parted -s $DISK mkpart primary linux-swap 5GiB 6GiB
sudo partprobe $DISK
sudo mkswap ${DISK}4
sudo swapon ${DISK}4
swapon --show
free -h
Make it permanent
UUID4=$(sudo blkid -s UUID -o value ${DISK}4)
echo "UUID=$UUID4  none  swap  defaults  0 0" | sudo tee -a /etc/fstab
sudo swapoff ${DISK}4 && sudo swapon -a
swapon --show

Verify your work

Run these before you consider the lab finished.

  1. sudo mount -a && echo 'fstab is valid'
  2. df -h | grep /mnt
  3. swapon --show
  4. reboot, then: df -h | grep /mnt && swapon --show
Break it, then fix it

Break:

echo 'UUID=00000000-dead-beef-0000-000000000000  /mnt/ghost  xfs  defaults  0 0' | sudo tee -a /etc/fstab

What you'll see: 'mount -a' fails. Had you rebooted instead, the system would have dropped to an emergency shell asking for the root password.

Fix:

sudo sed -i '/dead-beef/d' /etc/fstab && sudo mount -a

Why it matters: A bad fstab entry can stop a machine booting entirely. Two rules follow: back up fstab before editing it, and run 'mount -a' after every change. If a real system does drop to emergency mode, log in as root, remount / read-write, fix fstab, and reboot.

Now reboot

Run sudo reboot, then re-run every command in the verify list above. Anything that did not come back on its own would have scored zero on the exam. Fix it now, while you can still see what you did.
