Lab guide 11

Shell Scripting

Write the small, practical scripts the exam asks for: conditionals, loops, arguments, and command substitution. Nothing exotic is tested.

3-4 hours Weeks 1-10 complete
Before you start
  • Weeks 1-10 complete
  • Take a snapshot of both machines. You will break things on purpose.

1. The skeleton

Every script starts the same way.

Create, make executable, run
mkdir -p ~/bin && cd ~/bin
cat > hello.sh <<'EOF'
#!/bin/bash
echo "Hello from $(hostname), running as $(whoami)"
EOF
chmod +x hello.sh
./hello.sh

2. Conditionals

if with test or [ ]. Know the file, string, and numeric operators.

Branch on a condition
cat > check.sh <<'EOF'
#!/bin/bash
TARGET="/etc/passwd"

if [ -f "$TARGET" ]; then
    echo "$TARGET is a regular file"
elif [ -d "$TARGET" ]; then
    echo "$TARGET is a directory"
else
    echo "$TARGET does not exist"
fi
EOF
chmod +x check.sh && ./check.sh
The operators worth memorising
# Files:    -f (file)  -d (directory)  -e (exists)  -r -w -x (readable/writable/executable)
# Strings:  = (equal)  != (not equal)  -z (empty)  -n (not empty)
# Numbers:  -eq -ne -lt -le -gt -ge
man test | head -40
Numeric and string comparison side by side
cat > compare.sh <<'EOF'
#!/bin/bash
COUNT=$(who | wc -l)

if [ "$COUNT" -gt 1 ]; then
    echo "$COUNT users are logged in"
else
    echo "Only one session"
fi

if [ "$(whoami)" = "root" ]; then
    echo "Running as root"
else
    echo "Not root"
fi
EOF
chmod +x compare.sh && ./compare.sh

3. Loops

for over a list, a glob, and command output; while for reading input.

for, three ways
cat > loops.sh <<'EOF'
#!/bin/bash

for SERVICE in sshd chronyd firewalld; do
    printf '%-12s %s\n' "$SERVICE" "$(systemctl is-active $SERVICE)"
done

for FILE in /etc/*.conf; do
    echo "$(basename $FILE) has $(wc -l < $FILE) lines"
done

for USERNAME in $(getent passwd | awk -F: '$3 >= 1000 && $3 < 65534 {print $1}'); do
    echo "Regular user: $USERNAME"
done
EOF
chmod +x loops.sh && ./loops.sh
while, reading a file line by line
cat > readfile.sh <<'EOF'
#!/bin/bash
while read -r LINE; do
    case "$LINE" in
        \#*|"") continue ;;
    esac
    echo "config line: $LINE"
done < /etc/chrony.conf
EOF
chmod +x readfile.sh && ./readfile.sh | head

4. Script arguments

Explicitly in the objectives. Handle them, and fail cleanly when they are missing.

Positional parameters with validation
cat > args.sh <<'EOF'
#!/bin/bash

if [ "$#" -lt 2 ]; then
    echo "Usage: $(basename $0) <name> <count>" >&2
    exit 1
fi

NAME="$1"
COUNT="$2"

echo "Script:    $0"
echo "Arg count: $#"
echo "All args:  $@"

for i in $(seq 1 "$COUNT"); do
    echo "$i. Hello, $NAME"
done
EOF
chmod +x args.sh
./args.sh
./args.sh shea 3
echo "exit status: $?"

5. Using command output

Command substitution with $( ). Backticks work too but nest badly - use the modern form.

Capture and act on output
cat > report.sh <<'EOF'
#!/bin/bash

HOST=$(hostname -s)
WHEN=$(date '+%Y-%m-%d %H:%M')
USED=$(df -h / | awk 'NR==2 {print $5}')
LOAD=$(uptime | awk -F'load average:' '{print $2}')
USERS=$(getent passwd | awk -F: '$3 >= 1000 && $3 < 65534' | wc -l)

echo "===== $HOST at $WHEN ====="
echo "Root filesystem used: $USED"
echo "Load average:        $LOAD"
echo "Regular users:       $USERS"

if [ "${USED%\%}" -gt 80 ]; then
    echo "WARNING: root filesystem above 80 percent"
    exit 2
fi

exit 0
EOF
chmod +x report.sh && ./report.sh
echo "exit status: $?"

6. Exit statuses

Zero means success. Anything else means failure. Your scripts should follow that convention.

Check and return meaningfully
grep -q '^root:' /etc/passwd
echo "grep found it, status: $?"
grep -q '^nosuchuser:' /etc/passwd
echo "grep did not find it, status: $?"

systemctl is-active --quiet sshd && echo 'sshd is up' || echo 'sshd is down'

7. Final objective sweep

Before Week 12, go back to the source.

Re-read the official list and be honest
# Open the EX200 objectives and read every bullet.
# For each one, ask: could I do this right now, on a fresh machine, with no notes?
# Write down every 'no' or 'probably'. That list drives Week 12.

Verify your work

Run these before you consider the lab finished.

  1. cd ~/bin && for s in *.sh; do bash -n "$s" && echo "$s: syntax ok"; done
  2. ./args.sh shea 2
  3. ./report.sh; echo "exit: $?"
Break it, then fix it

Break:

sed -i 's/if \[ "$#" -lt 2 \]; then/if [ $# -lt 2 ] then/' ~/bin/args.sh

What you'll see: The script fails with a syntax error near an unexpected token.

Fix:

Restore the missing semicolon before then: 'if [ $# -lt 2 ]; then'. Check with: bash -n ~/bin/args.sh

Why it matters: 'bash -n script.sh' parses without executing and is the fastest way to find a syntax error. Also note the quoting: "$#" and "$1" in quotes protects you from empty or space-containing values - a habit worth having before the exam.

Now reboot

Run sudo reboot, then re-run every command in the verify list above. Anything that did not come back on its own would have scored zero on the exam. Fix it now, while you can still see what you did.
