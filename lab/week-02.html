Lab guide 2

Users, Groups, and Privileged Access

Create and manage local accounts and groups, age passwords, and grant sudo access the way the exam expects - in a drop-in file, not by editing the main sudoers.

2-3 hours Week 1 complete
Before you start
  • Week 1 complete
  • Root or sudo access on servera
  • Take a snapshot of both machines. You will break things on purpose.

1. Read the account databases first

You cannot manage what you cannot read. Every field here has a meaning worth knowing.

The three files that define an account
getent passwd shea
sudo getent shadow shea
getent group shea
What the fields mean
man 5 passwd
man 5 shadow
man 5 group

2. Create accounts

Create three accounts with different characteristics so you have something to manage.

A standard account, a system account, and one with a custom home
sudo useradd -c 'Standard account' analyst1
sudo useradd -r -s /sbin/nologin svc_backup
sudo useradd -d /opt/analyst2 -m -c 'Custom home' analyst2
getent passwd analyst1 svc_backup analyst2
Set passwords
echo 'ChangeMe123' | sudo passwd --stdin analyst1
sudo passwd -l svc_backup
Worth knowing

passwd --stdin is convenient in a lab. In the exam, plain interactive passwd is fine and less error-prone.

3. Password aging

Aging shows up in the objectives explicitly. Set it, then read it back.

Force a change at first login
sudo chage -d 0 analyst1
sudo chage -l analyst1
Maximum age, minimum age, and warning period
sudo chage -M 60 -m 7 -W 7 analyst1
sudo chage -l analyst1
Expire an account on a fixed date
sudo chage -E 2027-01-01 analyst2
sudo chage -l analyst2

4. Groups and membership

Know the difference between primary and supplementary membership, and never use usermod -G without -a.

Create groups and assign membership
sudo groupadd engineering
sudo groupadd -g 5000 contractors
sudo usermod -aG engineering analyst1
sudo usermod -aG engineering,contractors analyst2
id analyst1
id analyst2
Change a primary group
sudo usermod -g engineering analyst1
id analyst1
Worth knowing

usermod -G without -a replaces every supplementary group the user has. That single missing letter has failed real exams.

5. A shared group directory

This combines permissions, group ownership, and the set-GID bit - a very common exam-style task.

Create it and set group ownership
sudo mkdir -p /srv/engineering
sudo chgrp engineering /srv/engineering
sudo chmod 2770 /srv/engineering
ls -ld /srv/engineering
Prove the set-GID bit works
sudo -u analyst1 touch /srv/engineering/from-analyst1
ls -l /srv/engineering
Worth knowing

The 2 in 2770 is set-GID: new files inherit the directory's group instead of the creator's primary group. That is what makes a shared directory actually shared.

6. Privileged access

Always use a drop-in file. Editing /etc/sudoers directly is riskier and harder to undo.

Grant sudo to a group, safely
echo '%engineering ALL=(ALL) ALL' | sudo tee /etc/sudoers.d/engineering
sudo chmod 0440 /etc/sudoers.d/engineering
sudo visudo -c
Grant a single command without a password
echo 'analyst2 ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart sshd' | sudo tee /etc/sudoers.d/analyst2
sudo chmod 0440 /etc/sudoers.d/analyst2
sudo visudo -c
Test as the user
sudo -u analyst2 sudo -l

Verify your work

Run these before you consider the lab finished.

  1. id analyst1 analyst2
  2. sudo chage -l analyst1 | head -5
  3. ls -ld /srv/engineering # expect drwxrws--- and group engineering
  4. sudo visudo -c # must report 'parsed OK'
Break it, then fix it

Break:

echo 'this is not valid sudoers syntax' | sudo tee /etc/sudoers.d/broken

What you'll see: sudo may start refusing to run at all, which can lock you out of privilege escalation.

Fix:

Recover from an existing root shell, or boot to the emergency shell as taught in Week 5, then: rm /etc/sudoers.d/broken

Why it matters: Always run 'visudo -c' after touching anything under /etc/sudoers.d, and keep a root shell open in another terminal while you work. This is the one place where a typo can lock you out of your own machine.

Now reboot

Run sudo reboot, then re-run every command in the verify list above. Anything that did not come back on its own would have scored zero on the exam. Fix it now, while you can still see what you did.
