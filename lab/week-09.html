Lab guide 9

LVM, NFS, and autofs

Build logical volumes you can grow on demand, share a directory over the network, and mount it automatically only when it is needed.

4-5 hours Week 8 complete
Before you start
  • Week 8 complete
  • Free space or a third disk on servera
  • serverb reachable and able to run an NFS server
  • Take a snapshot of both machines. You will break things on purpose.

1. Build the LVM stack

Physical volume, then volume group, then logical volume. Always in that order.

Create physical volumes
sudo parted -s $DISK mkpart primary 6GiB 8GiB
sudo parted -s $DISK mkpart primary 8GiB 10GiB
sudo partprobe $DISK
sudo pvcreate ${DISK}5 ${DISK}6
sudo pvs
sudo pvdisplay ${DISK}5 | head
Create a volume group
sudo vgcreate labvg ${DISK}5
sudo vgs
sudo vgdisplay labvg | head
Create logical volumes - by size and by extents
sudo lvcreate -L 500M -n labdata labvg
sudo lvcreate -l 50%FREE -n labarchive labvg
sudo lvs
lsblk

2. Format and mount a logical volume

Filesystem and persistent mount
sudo mkfs.xfs /dev/labvg/labdata
sudo mkdir -p /mnt/labdata
LVUUID=$(sudo blkid -s UUID -o value /dev/labvg/labdata)
echo "UUID=$LVUUID  /mnt/labdata  xfs  defaults  0 0" | sudo tee -a /etc/fstab
sudo mount -a
df -h /mnt/labdata
Put something in it so you can prove it survives
echo 'written before the extend' | sudo tee /mnt/labdata/before.txt
sudo cat /mnt/labdata/before.txt

3. Extend a volume group and a logical volume

Growing storage online without losing data is a headline objective.

Add capacity to the volume group
sudo vgextend labvg ${DISK}6
sudo vgs
sudo pvs
Grow the logical volume and the filesystem together
df -h /mnt/labdata
sudo lvextend -L +800M -r /dev/labvg/labdata
sudo lvs
df -h /mnt/labdata
sudo cat /mnt/labdata/before.txt
The two-step form, for when -r is not available
# sudo lvextend -L +200M /dev/labvg/labdata
# XFS grows with:   sudo xfs_growfs /mnt/labdata
# ext4 grows with:  sudo resize2fs /dev/labvg/labdata
Worth knowing

The -r flag resizes the filesystem at the same time as the volume, which is why it is worth remembering. Note also that XFS can grow but cannot shrink - if a task asks you to shrink, the filesystem must be ext4.

4. Remove volumes cleanly

Tear down in reverse order
sudo lvremove -y labvg/labarchive
sudo lvs
# to remove the whole stack later:
#   sudo umount /mnt/labdata
#   sudo lvremove -y labvg/labdata
#   sudo vgremove -y labvg
#   sudo pvremove ${DISK}5 ${DISK}6

5. Export a directory over NFS

Run this section on serverb.

On serverb - install, export, and open the firewall
sudo dnf install -y nfs-utils
sudo mkdir -p /srv/nfsshare
sudo chmod 777 /srv/nfsshare
echo 'exported from serverb' | sudo tee /srv/nfsshare/hello.txt
echo '/srv/nfsshare  *(rw,sync,no_root_squash)' | sudo tee /etc/exports
sudo exportfs -rav
sudo systemctl enable --now nfs-server
sudo firewall-cmd --permanent --add-service=nfs
sudo firewall-cmd --permanent --add-service=mountd
sudo firewall-cmd --permanent --add-service=rpc-bind
sudo firewall-cmd --reload

6. Mount the NFS share

Back on servera.

Discover and mount by hand
sudo dnf install -y nfs-utils
showmount -e serverb
sudo mkdir -p /mnt/nfsshare
sudo mount -t nfs serverb:/srv/nfsshare /mnt/nfsshare
df -h | grep nfs
cat /mnt/nfsshare/hello.txt
Make it persistent
sudo umount /mnt/nfsshare
echo 'serverb:/srv/nfsshare  /mnt/nfsshare  nfs  defaults,_netdev  0 0' | sudo tee -a /etc/fstab
sudo mount -a
df -h | grep nfs
Worth knowing

_netdev tells systemd this mount needs the network up first. Without it, the boot can hang waiting for a share that is not reachable yet.

7. autofs

Mount on access, unmount when idle. Named explicitly in the objectives.

Remove the static mount first
sudo umount /mnt/nfsshare
sudo sed -i '\|serverb:/srv/nfsshare|d' /etc/fstab
grep nfs /etc/fstab || echo 'static NFS entry removed'
Configure the maps
sudo dnf install -y autofs
echo '/-  /etc/auto.direct' | sudo tee -a /etc/auto.master
echo '/mnt/nfsshare  -rw,sync  serverb:/srv/nfsshare' | sudo tee /etc/auto.direct
sudo systemctl enable --now autofs
sudo systemctl restart autofs
Prove on-demand behaviour
df -h | grep nfsshare || echo 'not mounted yet - correct'
ls /mnt/nfsshare
df -h | grep nfsshare
# wait for the idle timeout, then it unmounts itself again

8. Diagnose a permission problem

An explicit objective, and the diagnosis method matters more than the fix.

Create the problem, then work it out
sudo mkdir -p /srv/shared-data
sudo chown root:root /srv/shared-data
sudo chmod 700 /srv/shared-data
sudo -u analyst1 ls /srv/shared-data   # fails
ls -ld /srv/shared-data
id analyst1
Fix it properly with a group, not with 777
sudo chgrp engineering /srv/shared-data
sudo chmod 2775 /srv/shared-data
sudo -u analyst1 touch /srv/shared-data/works.txt
ls -l /srv/shared-data

Verify your work

Run these before you consider the lab finished.

  1. sudo lvs && sudo vgs && sudo pvs
  2. df -h /mnt/labdata # should show the extended size
  3. ls /mnt/nfsshare # triggers the autofs mount
  4. reboot, then confirm /mnt/labdata is mounted and 'ls /mnt/nfsshare' still works
Break it, then fix it

Break:

sudo lvextend -L +5G /dev/labvg/labdata

What you'll see: The command fails with 'Insufficient free space' because the volume group has no room left.

Fix:

Add capacity first: create another PV, then 'sudo vgextend labvg <new-pv>', then retry the lvextend.

Why it matters: LVM is a stack, and you can only grow a layer if the one beneath it has room. When an lvextend fails, check 'vgs' before anything else - the answer is almost always there in the VFree column.

Now reboot

Run sudo reboot, then re-run every command in the verify list above. Anything that did not come back on its own would have scored zero on the exam. Fix it now, while you can still see what you did.
