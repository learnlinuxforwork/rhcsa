Lab guide 3

Software: RPM, Repositories, and Flatpak

Install and remove software from every source the objectives name, including Flatpak, which is new to the RHEL 10 exam and missing from most older study material.

2-3 hours Week 2 complete
Before you start
  • Week 2 complete
  • Network access from servera
  • Take a snapshot of both machines. You will break things on purpose.

1. Query before you install

Half the software objectives are really about knowing what is already there.

What is installed, and what owns a file
rpm -qa | wc -l
rpm -qa | grep -i openssh
rpm -qf /etc/ssh/sshd_config
rpm -ql openssh-server | head
Search the repositories
dnf search nmap
dnf info nmap
dnf provides */htop

2. Install and remove RPM packages

From a repository, then from a downloaded file, so both paths are familiar.

From a configured repository
sudo dnf install -y nmap
rpm -q nmap
sudo dnf remove -y nmap
Groups and updates
dnf group list
sudo dnf check-update | head
sudo dnf update -y
From a local file
sudo dnf download nmap 2>/dev/null || sudo dnf install -y --downloadonly --downloaddir=/tmp nmap
sudo dnf install -y /tmp/nmap-*.rpm

3. Configure repository access

Writing a .repo file by hand is explicitly in the objectives. Do it manually rather than with a helper.

Write the repo definition
sudo tee /etc/yum.repos.d/local-lab.repo >/dev/null <<'EOF'
[local-lab]
name=Local Lab Repository
baseurl=file:///mnt/repo
enabled=1
gpgcheck=0
EOF
cat /etc/yum.repos.d/local-lab.repo
List, enable, and disable
dnf repolist
dnf repolist --all | head
sudo dnf config-manager --set-disabled local-lab
dnf repolist
sudo dnf config-manager --set-enabled local-lab
Use a repository once without enabling it
sudo dnf --disablerepo='*' --enablerepo='local-lab' list available 2>/dev/null | head
Worth knowing

gpgcheck=0 is acceptable for a local lab repo you created. For a real remote repository, point gpgkey at the key and leave gpgcheck=1.

4. Flatpak

New in the RHEL 10 objectives. Configure a remote, then install, run, and remove an application.

Install the tooling and add a remote
sudo dnf install -y flatpak
flatpak remotes
flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
flatpak remotes
Search, install, list, and run
flatpak search text-editor | head
flatpak install -y flathub org.gnome.TextEditor
flatpak list
flatpak run org.gnome.TextEditor --help 2>/dev/null | head -3
Remove it and clean up
flatpak uninstall -y org.gnome.TextEditor
flatpak uninstall --unused -y
flatpak list
Remove a remote
flatpak remote-delete flathub
flatpak remotes
Worth knowing

An RPM installs into the system as root and integrates with system libraries. A Flatpak is a sandboxed, self-contained application bundle that can be installed per-user. Being able to state that difference is fair game.

Verify your work

Run these before you consider the lab finished.

  1. dnf repolist | grep -i local-lab
  2. flatpak remotes
  3. rpm -q nmap || echo 'nmap correctly removed'
  4. sudo dnf history | head -5
Break it, then fix it

Break:

sudo sed -i 's|^baseurl=.*|baseurl=file:///mnt/does-not-exist|' /etc/yum.repos.d/local-lab.repo

What you'll see: dnf commands fail or hang with a repository error referencing local-lab.

Fix:

sudo sed -i 's|^baseurl=.*|baseurl=file:///mnt/repo|' /etc/yum.repos.d/local-lab.repo && sudo dnf clean all && dnf repolist

Why it matters: A broken repo file breaks every dnf operation, not just the one that uses it. Read the error text - it names the offending repository. 'dnf clean all' after fixing a repo is almost always necessary.

Now reboot

Run sudo reboot, then re-run every command in the verify list above. Anything that did not come back on its own would have scored zero on the exam. Fix it now, while you can still see what you did.
